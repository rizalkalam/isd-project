## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding |
| sm | 8px | Compact element spacing, gap between badge and text |
| md | 16px | Default element spacing, table cell padding (px-4) |
| lg | 24px | Section padding, card padding (p-6), stat-card padding (24px) |
| xl | 32px | Layout gaps, page padding, header margin-bottom |
| 2xl | 48px | Major section breaks, empty state vertical padding |
| 3xl | 64px | Page-level spacing (reserved, not currently used in new pages) |

Exceptions:
- Stat cards use 40px top padding on `.page-dashboard` (from index.css `.page-dashboard` rule — 40px).
- Stats grid gap: 18px (closest to md, intentional design exception in existing `.stats-grid`).
- Container max-width: `max-w-6xl` (same as existing Loans.tsx). Dashboard uses same constraint.

Source: `frontend/src/index.css`, `frontend/src/pages/admin/Loans.tsx`, `frontend/src/pages/admin/Inventory.tsx`

Accent reserved for:

4. `.auth-chip` background tint and text — auth pages only

Status badge color map (extends existing `STATUS_BADGE_VARIANT` in Loans.tsx):

| Status | Badge Variant | Background | Text |

| ACTIVE | `default` | `bg-slate-900` | `text-slate-50` |

- Apply `className="... bg-amber-50 border-l-4 border-amber-400"` to `<tr>` when `isOverdue === true`.
- This is IN ADDITION to the OVERDUE badge on the status cell.

## Component Inventory

### New Components (Phase 3)

#### 1. `frontend/src/pages/admin/Dashboard.tsx`
Route: `/admin/dashboard`
Role: Librarian dashboard — metrics overview + filtered loans table.

Layout structure:
```
<div class="container mx-auto p-6 max-w-6xl">
  <header class="mb-8">                     ← page header (h1 + subtitle)
  <section class="grid grid-cols-2 md:grid-cols-4 gap-4 mb-8">  ← 4 metric cards
  <section>                                  ← loans table with filter tabs
    <div class="flex gap-2 mb-4">           ← filter button row (ALL/PENDING/ACTIVE/OVERDUE)
    <div class="rounded-xl border overflow-hidden">  ← table container
```

Metric cards (4 total) — reuse `Card`, `CardHeader`, `CardTitle`, `CardDescription` from `card.tsx`:

| Card | Metric | Icon (lucide-react) |
|------|--------|---------------------|
| Active Loans | Count of `status=ACTIVE` loans | `BookOpen` |
| Pending Requests | Count of `status=PENDING` loans | `Clock` |
| Overdue Items | Count of overdue loans | `AlertTriangle` |
| Total Loans | All-time loan count | `Library` |

Overdue Items card: `CardTitle` text uses `text-amber-600` when count > 0, `text-slate-950` when 0.

Filter tabs (status filter):
- Render as a row of `<button>` elements: ALL | PENDING | ACTIVE | OVERDUE
- Active filter button: `bg-slate-900 text-white` rounded-md px-3 py-1 text-sm font-medium
- Inactive filter button: `border border-slate-200 text-slate-600` same sizing, hover: `hover:bg-slate-50`

Table columns (same structure as `Loans.tsx` — extend, do not duplicate):
Student | Book Title | Status | Due Date | Actions

- Due Date cell: display `—` when `due_date` is null (PENDING/APPROVED rows).
- Overdue row: add `bg-amber-50` background + `border-l-4 border-amber-400` left accent on the `<tr>`.
- Actions column: reuse same `Approve` / `Mark Active` / `Mark Returned` / `Reject` button pattern from `Loans.tsx`. No new action types on Dashboard.

Loading state: Same spinner pattern as `Loans.tsx`:
```jsx
<div className="flex items-center justify-center min-h-[400px]">
  <div className="animate-spin rounded-full h-12 w-12 border-b-2 border-slate-900" />
</div>
```

Empty state (no loans at all):
```jsx
<div className="text-center py-20 bg-slate-50 rounded-2xl border border-dashed">
  <p className="text-slate-500">No loans yet. Approved requests will appear here.</p>
</div>
```

Empty state (filter active, no matching rows):
```jsx
<div className="text-center py-12 bg-slate-50 rounded-xl border border-dashed">
  <p className="text-slate-500">No {filterLabel} loans found.</p>
</div>
```

## Interaction Contract

### Dashboard filter tabs
- Default selected filter on page load: `ALL`
- Filter is client-side only — all loans are fetched once; the active filter value controls which rows render.
- Selected tab gets `bg-slate-900 text-white`; deselected tabs get `border border-slate-200 text-slate-600`.
- Tab switch is immediate (no loading state — data is already in memory).
- Keyboard: tabs are `<button>` elements, naturally focusable. No custom keyboard handling required.

### Overdue detection
- Computed client-side after data fetch: a loan is overdue when `status === 'ACTIVE' && due_date && new Date(due_date) < new Date()`.
- The `/api/v1/loans/overdue` endpoint is the authoritative source for the dashboard's Overdue Items metric card count.
- The dashboard table applies the overdue row style using this same client-side check on the full loans list.

### Metric card loading
- Cards render their count as `—` (em dash) while the stats fetch is in flight.
- No skeleton/shimmer on cards — the em dash placeholder is sufficient for MVP.

### Student loans page
- Sorted by `created_at` descending (most recent first).
- No pagination for MVP — render all loans in a single list.
- No filter controls — student sees all their own loans.

### Transition / animation
- Row hover: `hover:bg-slate-50 transition-colors` (same as Loans.tsx).
- Overdue row hover: `hover:bg-amber-100 transition-colors` (slightly deeper amber on hover).
- No other animations beyond existing spinner pattern.

### Responsive breakpoints
- Dashboard metric cards: `grid-cols-2 md:grid-cols-4` — 2 columns on mobile, 4 on md+.
- Dashboard table: horizontal scroll on small screens — wrap table in `overflow-x-auto`.
- Student loans list: single column at all breakpoints (stacked flex rows, no grid).
- Container: `container mx-auto p-6 max-w-6xl` for dashboard; `max-w-4xl` for student loans page.
