## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → /api/v1/loans/overdue | Unauthenticated or wrong-role callers must be rejected |
| HTTP client → /api/v1/loans/dashboard-stats | Unauthenticated or wrong-role callers must be rejected |
| HTTP client → /api/v1/loans/my | Student must only receive their own loans, not others' |
| DB → due_date value | Must never be set by client input — only by server logic at ACTIVE transition |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | GET /loans/overdue | mitigate | `deps.check_role(UserRole.LIBRARIAN)` guard raises HTTP 403 for non-librarian callers; verified in acceptance criteria |
| T-03-02 | Elevation of Privilege | GET /loans/dashboard-stats | mitigate | `deps.check_role(UserRole.LIBRARIAN)` guard raises HTTP 403 for non-librarian callers |
| T-03-03 | Information Disclosure | GET /loans/my | mitigate | Query filters `Loan.user_id == current_user.id` — student cannot enumerate other students' loans; `deps.check_role(UserRole.STUDENT)` blocks librarians from using this route |
| T-03-04 | Tampering | due_date field | mitigate | `due_date` is never read from request body — only set by server at ACTIVE transition via `datetime.utcnow() + timedelta(days=14)`; field is absent from LoanCreate and LoanStatusUpdate schemas |
| T-03-05 | Spoofing | JWT auth on all new endpoints | accept | Covered by existing `get_current_user` dependency chain (established in Phase 1 auth layer); no new auth surface added |
| T-03-SC | Tampering | npm/pip installs | accept | No new packages installed in this plan; only existing SQLModel, FastAPI, and axios in use |
