## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /admin/dashboard | Page must only be reachable by librarian-role users |
| Browser → /student/loans | Page must only return the authenticated student's own loans |
| Client-side overdue detection | Client clock can be manipulated — backend /overdue endpoint is authoritative for overdue count |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Elevation of Privilege | /admin/dashboard page | accept | Route is UI-only; the actual data is protected by backend role guards (T-03-01, T-03-02 from Plan 01). A student navigating to /admin/dashboard will see API 403 errors rather than data. Role-based nav links can be added in a future phase. |
| T-03-07 | Information Disclosure | Dashboard table displays all loans | accept | All loan data on the dashboard is fetched via `GET /loans/` which is already a LIBRARIAN-only endpoint (Phase 2). No new data exposure surface. |
| T-03-08 | Tampering | Client-side isOverdue function | accept | Client clock manipulation can cause incorrect overdue display; however, authoritative overdue count uses `getDashboardStats` from backend which computes server-side. Display inconsistency is cosmetic for MVP. |
| T-03-09 | Information Disclosure | Student loans page query key ["my-loans"] | mitigate | `getMyLoans` calls `GET /loans/my` which is guarded by `check_role(UserRole.STUDENT)` and filters `Loan.user_id == current_user.id`; React Query cache is per-session and cleared on logout |
| T-03-SC | Tampering | npm/pip installs | accept | No new packages installed in this plan; lucide-react and @tanstack/react-query are already in package.json from Phase 1/2 |
</threat_model>
